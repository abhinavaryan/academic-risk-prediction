# Methodology

This document explains how the study is designed. The numbers live in
[`reports/results.md`](../reports/results.md); they are regenerated by the pipeline and never
typed by hand.

## 1. Research question

> How early in a course can we reliably identify students who will fail or withdraw, and which
> signals matter most?

## 2. Data

**Open University Learning Analytics Dataset** (Kuzilek et al., 2017, CC BY 4.0), downloaded from
the UCI repository. The archive's SHA-256 is verified before use (`riskml/oulad/download.py`).

| Table | Rows | Used for |
|---|---|---|
| studentInfo | 32,593 | demographics, prior attempts, credits, **final_result** (label) |
| studentRegistration | 32,593 | registration / unregistration day |
| courses | 22 | course length |
| assessments | 206 | assessment type, deadline, weight |
| studentAssessment | 173,912 | submission day, score, banked flag |
| vle | 6,364 | activity type of each learning resource |
| studentVle | 10,655,280 | daily clicks per student per resource |

**Cleaning rules** (`riskml/oulad/load.py`): `?` means missing; the IMD band `10-20` (missing its
`%` in the source) becomes `10-20%`; VLE clicks are joined with the resource's activity type.

## 3. Problem formulation

- **Unit of analysis:** a registration (one student in one module presentation). A student who
  takes two modules appears twice, so every split is grouped by student.
- **Label:** `at_risk = 1` if `final_result ∈ {Fail, Withdrawn}`, else 0 (Pass, Distinction).
- **Prediction day (cutoff) D ∈ {0, 30, 60, 90, 120, 150, 180}**, counted in days from the module
  start. Day 60 was fixed as the primary cutoff before any results were seen.
- **Population at D:** registrations that have not unregistered by day D. A student who already
  withdrew is no longer someone you can warn.

## 4. Features (49, computed for each cutoff)

Only events dated **on or before D** are used (`riskml/oulad/features.py`):

| Group | Features |
|---|---|
| Demographic (8) | gender, region, highest education, IMD band, age band, disability, previous attempts, studied credits |
| Course (3) | module, start semester (B/J), course length |
| Registration (1) | registration day relative to the start |
| VLE engagement (23) | total clicks, active days, distinct resources, pre-course clicks, clicks in the last 14 days, days since last activity, first activity day, weekly click trend (least-squares slope), clicks and active days relative to the class median, clicks per activity type (12 types + other) |
| Assessment (14) | assessments due, submitted, missed, submission rate, mean / weighted / minimum score, scores below 40, mean days before the deadline, late submissions, banked results, tutor- and computer-marked averages, score relative to the class median |

**Leakage controls**
- Exams (held at the end) are excluded.
- Class-relative features only use classmates' data up to the same day. That information is
  available to a real teacher on that day.
- `tests/oulad/test_features.py::test_no_future_information` adds clicks and submissions dated
  after the cutoff and asserts that the feature matrix is unchanged.
- Known simplification: a score is assumed known on the submission day. Real marking delays would
  make early prediction slightly harder.

## 5. Validation protocol

1. **Temporal hold-out.** Train on presentations 2013B, 2013J and 2014B; test on **2014J**, the
   most recent semester. This mimics deployment: learn from the past, predict the next intake.
2. **Model selection** uses only the training semesters: 5-fold `StratifiedGroupKFold`
   (stratified by label, grouped by `id_student`). The pre-registered selection metric is
   cross-validated ROC-AUC.
3. **Decision threshold.** For each model, the threshold that maximises F1 on its out-of-fold
   predictions. It is then applied unchanged to the test semester.
4. **Hyper-parameter tuning.** Optuna TPE with 3-fold grouped CV inside the training semesters:
   - 30 trials each for HistGradientBoosting, LightGBM and XGBoost
   - 15 trials for Random Forest
5. **Stacked ensemble.** A logistic-regression meta-learner is fitted on the out-of-fold
   probabilities of six strong base models. Out-of-fold stacking avoids leakage.
6. **Single test evaluation** of every model, with:
   - 95% percentile-bootstrap confidence intervals (1,000 resamples)
   - McNemar's test against the best model, to check whether two models really differ
   - curves: ROC, precision–recall and calibration

## 6. Models

| Family | Models |
|---|---|
| Baseline | majority-class prior |
| Linear / probabilistic | Logistic Regression, Gaussian Naive Bayes, Linear SVM (calibrated) |
| Instance-based | k-Nearest Neighbours |
| Trees & bagging | Decision Tree, Random Forest (+ tuned), Extra Trees |
| Boosting | AdaBoost, HistGradientBoosting (+ tuned), LightGBM (+ tuned), XGBoost (+ tuned), CatBoost |
| Neural network | Multi-layer perceptron (64-32, early stopping) |
| Ensemble | Stacked ensemble |

All share one preprocessing recipe:
- numeric columns: median imputation with missing-value indicators, standardised for the
  distance-, margin- and gradient-based models
- categorical columns: constant imputation and one-hot encoding, with rare levels (< 1%) pooled

### Deployment choice

The deployed model is the **scikit-learn-native model with the best cross-validated ROC-AUC**.
Two reasons:
- **Runtime constraints:** LightGBM needs a system OpenMP library that the serverless runtime may
  not provide, and CatBoost alone is 268 MB installed.
- **Security:** scikit-learn models can be stored in the skops format and loaded without pickle.

The best model overall is reported next to it, so the cost of this engineering choice is visible.

## 7. Early-warning timeline

The full feature build, cross-validation, threshold tuning and test evaluation are repeated at
every cutoff for four representative models plus the deployed one. One deployed model is saved
per cutoff, so the live predictor can answer "what is the risk on day 30?".

## 8. Explainability

- **Global (deployed model):** permutation importance, i.e. the drop in test ROC-AUC when a
  feature is shuffled (5 repeats).
- **Global (cross-check):** TreeSHAP of the tuned LightGBM model, aggregated from one-hot columns
  back to raw features.
- **Local (every prediction):** baseline-replacement attribution. The student is re-scored with
  one feature at a time set to the typical value (training median or mode); the change in risk is
  that feature's impact. It is exact for the deployed model and easy to explain to a teacher.
  Demographic and course features are labelled *context*, because they are not things a teacher
  can or should act on.

## 9. Fairness audit

On the test semester, at the deployed threshold, for gender, disability, age band, IMD band and
prior education:
- flag rate (demographic parity)
- recall / true-positive rate (equal opportunity)
- false-alarm rate (false-positive rate)

Max-min gaps across groups are reported. The ablation retrains the model **without** gender,
disability, age, deprivation and region, to show the accuracy cost of a "protected-attribute-free"
model and its effect on the gaps.

## 10. Bring-your-own-data training (`riskml/custom`)

1. **Read the upload safely:**
   - CSV delimiter sniffing; encodings utf-8 / utf-8-sig / cp1252 / latin-1 / utf-16
   - `.xlsx` with a zip-bomb guard and no formula evaluation
   - size, row and column limits
2. **Profile every column:** numeric (including `85%`), categorical, ID, personal data (names,
   e-mails, phones), free text, constant or empty. Suggest the result column and which values mean
   *at risk* or *unknown*.
3. **Label the rows:** known results are training rows. Blank or "unknown" results (e.g.
   `Enrolled`) are scored. A numeric result can also be thresholded ("at risk if marks < 40").
4. **Leakage screen:** a column that alone predicts the label with AUC ≥ 0.98 is excluded with a
   warning.
5. **Model comparison:** up to eight scikit-learn models, stratified k-fold CV, under a time
   budget. The F1-optimal threshold is taken from out-of-fold predictions.
6. **Scoring:** the best model is refit on all labeled rows and scores the unknown rows. Labeled
   rows keep their honest out-of-fold probability.
7. **Reasons:** baseline-replacement attribution, giving up to three risk-raising factors per
   student.

## 11. Limitations

- One UK distance-learning university, 2013–2014. Campus colleges, other countries and later
  years differ; the bring-your-own-data mode exists for that reason.
- Observational data: feature importance is predictive, not causal.
- A risk score should start a supportive human conversation. It must never trigger an automatic
  decision about a student.

## 12. Reproducibility

- Seeds fixed (`SEED = 42`), exact dependency pins, a verified data checksum.
- One command: `make research`.
- The artifacts manifest records the scikit-learn and skops versions, the data hash and the
  SHA-256 of every served file.
